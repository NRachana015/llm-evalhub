## 🧠 Overview

**LLM-EvalHub** is an automated **Large Language Model evaluation and analytics platform** designed to benchmark, analyze, and compare responses generated by different language models.

The platform allows users to run controlled evaluation experiments using the **same dataset and prompt configuration**, measure response quality through multiple evaluation metrics, use an **LLM-as-a-Judge** for semantic assessment, track performance and cost, and compare results across experiments.

The system is designed around a complete evaluation lifecycle:

**Dataset → Prompt → LLM → Response → Evaluation → LLM Judge → Analytics → Run Comparison**

## 📊 Evaluation Framework

LLM-EvalHub evaluates generated responses using **12 evaluation dimensions**.

### 🔹 Standard Automated Metrics

| Metric            | Purpose                                |
| ----------------- | -------------------------------------- |
| Exact Match       | Measures exact output agreement        |
| Token F1          | Measures token-level overlap           |
| TF-IDF Similarity | Measures lexical similarity            |
| Correctness       | Evaluates answer correctness           |
| Relevance         | Measures relevance to the question     |
| Faithfulness      | Measures support from provided context |
| Coherence         | Evaluates response consistency         |

### 🔹 LLM-as-a-Judge Metrics

The platform additionally uses an LLM judge to perform semantic evaluation.

| Metric        | Purpose                                           |
| ------------- | ------------------------------------------------- |
| Correctness   | Determines whether the response answers correctly |
| Relevance     | Evaluates whether the response stays focused      |
| Faithfulness  | Checks whether claims are supported by context    |
| Coherence     | Evaluates logical consistency                     |
| Hallucination | Identifies unsupported information                |

Each judge evaluation can also provide an **explanation** along with the score.

## ⚖️ LLM-as-a-Judge

LLM-EvalHub includes an **LLM-as-a-Judge evaluation layer** for semantic response assessment.

The current implementation supports a Gemini-based judge with a deterministic local fallback for pipeline reliability.

```text
Generated Response
        │
        ▼
   Judge Model
        │
        ├── Correctness
        ├── Relevance
        ├── Faithfulness
        ├── Coherence
        └── Hallucination
        │
        ▼
 Score + Explanation
```

### Judge Reliability

The evaluation system records whether a judge result was produced by:

* 🧠 Real LLM Judge
* 🔧 Local deterministic fallback

This makes evaluation runs traceable and helps distinguish genuine LLM-based assessments from fallback evaluations.

## 🛡️ Failure Handling

LLM evaluation pipelines can fail because of API limits, unavailable models, network problems, or provider-side errors.

LLM-EvalHub handles model failures independently.

For example:

```text
Evaluation Run
      │
      ├── Gemini ────── ❌ API Failure
      │
      └── Codestral ─── ✅ Completed
                           │
                           ▼
                    Store Successful
                       Evaluation
```

Instead of terminating the complete experiment when one model fails, the system records:

* Successful models
* Failed models
* Failure status
* Error information
* Completed evaluation results

Run statuses include:

* `completed`
* `completed_with_errors`
* `failed`

## 🚀 Getting Started

### 🔹 Clone Repository

```bash
git clone https://github.com/NRachana015/llm-evalhub.git
cd llm-evalhub
```

---

### 🔹 Create Virtual Environment

#### Windows

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

---

### 🔹 Install Dependencies

```powershell
pip install -r requirements.txt
```

---

### 🔹 Configure Environment Variables

Create a `.env` file using `.env.example`:

```text
DATABASE_URL=sqlite:///./eval_dashboard.db

GOOGLE_API_KEY=your_google_api_key
OPENAI_API_KEY=your_openai_api_key
MISTRAL_API_KEY=your_mistral_api_key

JUDGE_MODEL=gemini-3.6-flash
```

Only add API keys for providers you intend to use.

**Never commit `.env` or API keys to GitHub.**

---

## ▶️ Run the Application

.\venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8001

## 💡 Why LLM-EvalHub?

Modern LLM applications require more than simply generating responses.

A reliable evaluation workflow needs to answer:

```text
Is the response correct?
        ↓
Is it relevant?
        ↓
Is it supported by the context?
        ↓
Does it contain hallucinations?
        ↓
How long did it take?
        ↓
How much did it cost?
        ↓
How does it compare with another experiment?
```

**LLM-EvalHub brings these evaluation stages together into a single experimental platform.**
